# Voluntary Product Accessibility Template (VPAT®) Version 2.5

## Accessibility Conformance Report

### WCAG 2.1 Edition

---

## Product Information

| Field | Details |
|---|---|
| **Product Name** | Paper LMS |
| **Product Version** | 1.0 |
| **Product Description** | Web-based Learning Management System (LMS) for K-12 schools. Paper LMS is a single-page application (SPA) with a React frontend and Go backend, providing course management, assignments, grading, quizzes, discussions, file management, and messaging. |
| **Date of Report** | February 17, 2026 |
| **Contact Information** | Paper LMS Development Team |
| **Evaluation Methods Used** | Manual code review of all 40 frontend pages and 14 shared components; manual keyboard navigation testing; DOM inspection for ARIA attributes and semantic HTML; review of Tailwind CSS utility classes for visual presentation. No automated accessibility testing framework (e.g., axe-core, pa11y) is currently integrated. No assistive technology testing (NVDA, JAWS, VoiceOver) has been formally conducted. |

### Terms

The terms used in the Conformance Level column are defined as follows:

| Term | Definition |
|---|---|
| **Supports** | The functionality of the product has at least one method that meets the criterion without known defects or meets with equivalent facilitation. |
| **Partially Supports** | Some functionality of the product does not meet the criterion. |
| **Does Not Support** | The majority of product functionality does not meet the criterion. |
| **Not Applicable** | The criterion is not relevant to the product. |

Grade feedback uses `ring-green-400`/`ring-red-400` which depends on color perception, though the transient animation is supplementary to the saved value display. |

The DocumentViewer annotation tool selection and canvas drawing interactions may not be fully keyboard-accessible. |
| [2.1.2 No Keyboard Trap](https://www.w3.org/WAI/WCAG21/Understanding/no-keyboard-trap.html) | Supports | The FocusTrap component implements Escape key handling (`onEscape` callback) to release focus. However, there is no mechanism for users to request extended time, pause the timer, or receive a warning before time expires (beyond the visible countdown). Note: The assignment overrides system supports per-student accommodations which could be used to extend quiz time, but no self-service time extension is available to the student during the quiz. |
| [2.2.2 Pause, Stop, Hide](https://www.w3.org/WAI/WCAG21/Understanding/pause-stop-hide.html) | Supports | The application does not contain auto-updating, moving, blinking, or scrolling content that starts automatically and lasts more than five seconds. The quiz countdown timer is informational text that updates once per second. The offline indicator appears/disappears based on network state changes (event-driven, not auto-scrolling). Loading states display static text ("Loading courses..."). |
| [2.3.1 Three Flashes or Below Threshold](https://www.w3.org/WAI/WCAG21/Understanding/three-flashes-or-below-threshold.html) | Supports | The application does not contain any content that flashes more than three times per second. Transitions use Tailwind CSS `transition-*` utilities which are smooth opacity/color changes, not flashes. |

ARIA landmarks (`role="banner"`, `role="main"`, `aria-label` on `<nav>`) provide additional bypass mechanisms for screen reader users. |
| [2.4.2 Page Titled](https://www.w3.org/WAI/WCAG21/Understanding/page-titled.html) | Partially Supports | The HTML document has a `<title>` element set to "Paper LMS". This means screen reader users are not informed of page context changes via the document title. |
| [2.4.3 Focus Order](https://www.w3.org/WAI/WCAG21/Understanding/focus-order.html) | Partially Supports | Focus order generally follows the visual layout (left-to-right, top-to-bottom). The FocusTrap correctly cycles focus within modal dialogs. The skip-to-content link moves focus to the main content area. However, focus management after route changes in the SPA is not explicitly handled — focus may remain on a removed element or reset to the document body rather than moving to the new page's heading or main content. |
| [2.4.4 Link Purpose (In Context)](https://www.w3.org/WAI/WCAG21/Understanding/link-purpose-in-context.html) | Partially Supports | Most links have descriptive text content (e.g., "Dashboard", "Courses", course names). Navigation links include both icon and text. The Rich Content Editor's accessibility checker flags empty links in authored content. However, the logout button uses only an icon (`<LogOut>`) with a `title` attribute but no `aria-label`, which may not be announced by all screen readers. Some programmatically generated links (e.g., "Browse Courses") have clear text. |

The DocumentViewer's freehand annotation tool requires path-based pointer gestures (click-and-drag drawing) which do not have a single-pointer alternative for the same function. All other functionality (buttons, links, form inputs) uses simple activation. |
| [2.5.2 Pointer Cancellation](https://www.w3.org/WAI/WCAG21/Understanding/pointer-cancellation.html) | Supports | Interactive elements use standard HTML `<button>` and `<a>` elements which activate on the `click` event (up-event). The Rich Content Editor toolbar uses `onMouseDown` with `preventDefault` to prevent focus loss, but the action executes immediately on down-event; however, since these are toolbar formatting commands (not destructive actions), the impact is minimal. The DocumentViewer's freehand drawing completes on pointer-up. |
| [2.5.3 Label in Name](https://www.w3.org/WAI/WCAG21/Understanding/label-in-name.html) | Supports | Buttons and links have accessible names that match or contain their visible text labels. Navigation links use their visible text as the accessible name. |
| [2.5.4 Motion Actuation](https://www.w3.org/WAI/WCAG21/Understanding/motion-actuation.html) | Not Applicable | The application does not use device motion or user motion (e.g., shaking, tilting) to trigger any functionality. |
| [3.1.1 Language of Page](https://www.w3.org/WAI/WCAG21/Understanding/language-of-page.html) | Supports | The `<html>` element includes `lang="en"` in `index.html`, correctly identifying the page language as English. |
| [3.1.2 Language of Parts](https://www.w3.org/WAI/WCAG21/Understanding/language-of-parts.html) | Does Not Support | User-generated content (course descriptions, discussion posts, assignment instructions) may be in languages other than English. The application does not support RTL (right-to-left) languages. |

| [3.2.2 On Input](https://www.w3.org/WAI/WCAG21/Understanding/on-input.html) | Supports | Form inputs do not cause automatic context changes. Login/registration forms require explicit submit button activation. |
| [3.3.1 Error Identification](https://www.w3.org/WAI/WCAG21/Understanding/error-identification.html) | Partially Supports | Login/registration errors are displayed as visible text messages below the form. However, error messages are not consistently associated with their related form fields via `aria-describedby` or `aria-invalid`, and the error text on the login page is not within an element with `role="alert"` for immediate screen reader announcement. |
| [3.3.2 Labels or Instructions](https://www.w3.org/WAI/WCAG21/Understanding/labels-or-instructions.html) | Partially Supports | Form fields on the login/registration page have visible `<label>` elements. | [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value.html) | Partially Supports | Standard HTML elements are used for their intended purposes (buttons, links, inputs, headings). The GradeInput's success/error feedback is visual-only (colored ring animation) without a screen reader announcement. |

## Revised Section 508 Report

### Chapter 3: Functional Performance Criteria

| Criteria | Conformance Level | Remarks and Explanations |

| 302.1 Without Vision | Partially Supports | ARIA landmarks, semantic HTML, skip navigation, focus traps, and live regions provide structural support for screen reader users. Known gaps include: GradeInput non-editing state is not keyboard-focusable; document title does not update on SPA navigation; some status messages are visual-only. |

| 302.5 With Limited Hearing | Partially Supports | Same as 302.4. No caption support for multimedia content. |

| 302.8 With Limited Reach and Strength | Supports | The application does not require simultaneous actions or sustained physical effort. Keyboard shortcuts use standard modifier+key combinations. Touch targets on mobile viewports benefit from responsive layout spacing. |
| 302.9 With Limited Language, Cognitive, and Learning Abilities | Partially Supports | The interface uses clear, concise labels and standard LMS terminology familiar to educators. Consistent navigation patterns are maintained. However, the application is English-only with no internationalization (i18n), no simplified language mode, and no RTL language support. |
